# Модуль 5 — ИИ-агенты: продвинутый уровень

Продолжаем на Ductor: учим агента отвечать по твоим документам, работать с файлами и подключаться к почте, таблицам и сайту. В итоге — агент, которому можно доверить реальную рутину, но под твоим контролем.

## Ключевые понятия

- **База знаний** — набор твоих документов (FAQ, прайс, регламенты, тон общения), по которым агент отвечает вместо того, чтобы выдумывать.
- **Рабочая папка агента** — папка на сервере, где лежат файлы агента. Всё, что ты туда положишь, агент может прочитать и использовать.
- **Долговременная память** — файл, куда агент записывает устойчивые факты о тебе и бизнесе. Она сохраняется между разговорами.
- **Коннектор** — способ подключить агента к внешнему сервису: почте, Google Sheets, диску. Бывает через MCP-сервер, API или вебхук.
- **MCP (Model Context Protocol)** — открытый стандарт, через который ИИ-агент получает доступ к инструментам и данным внешних сервисов.
- **Вебхук** — адрес, на который внешний сервис (например, форма на сайте) сам отправляет данные, и агент сразу начинает работу.
- **Принцип минимальных прав** — даёшь агенту ровно тот доступ, который нужен для задачи: читать таблицу, а не управлять всем аккаунтом.
- **Человек в контуре** — агент готовит черновик, а отправляет наружу (клиенту, в соцсети, по почте) только после твоего «ок».

## Пошагово

1. Собери материалы для базы знаний: FAQ (10-30 частых вопросов с ответами), актуальный прайс, регламенты (сроки, возвраты, оплата), описание тона общения с 2-3 примерами удачных ответов.
2. Приведи их в порядок: один документ — одна тема, понятные названия файлов (`faq.md`, `price.md`, `rules.md`, `tone.md`), в каждом — дата обновления.
3. Отправь файлы агенту в Telegram и попроси сохранить их в рабочую папку в отдельный раздел, например `knowledge/`.
4. Попроси агента запомнить в долговременной памяти главное правило: «отвечай клиентам только по файлам из knowledge/, если ответа нет — так и скажи».
5. Проверь базу: задай 5-10 вопросов, ответы на которые знаешь. Отдельно задай 2-3 вопроса, которых в базе нет, — агент должен честно сказать «не знаю».
6. Потренируйся с файлами: отправь PDF или таблицу, попроси разобрать, а потом сгенерировать документ (КП, отчёт) и прислать его файлом.
7. Выбери один коннектор под свою задачу (почта, Google Sheets или форма сайта). Заведи для агента отдельный аккаунт или ключ с минимальными правами.
8. Положи ключи в файл `.env` на сервере (агент или мастер на созвоне покажет, как). Никогда не вставляй ключи и пароли в чат.
9. Для формы сайта создай вебхук: агент выдаст адрес и токен, их нужно указать в настройках формы или сервиса автоматизации.
10. Составь 10 тест-кейсов (типичные, сложные, провокационные запросы) и прогони их. Ошибки исправляй правкой базы знаний или инструкций.
11. Включи правило «человек в контуре»: всё, что уходит наружу, агент сначала показывает тебе с кнопками «Отправить / Исправить».

## Готовые промпты

**Загрузка базы знаний**

```
Я отправляю тебе файлы для базы знаний: [список файлов].
Сохрани их в рабочую папку в раздел knowledge/, каждый — отдельным файлом
с понятным названием. Затем:
1. Кратко перечисли, что в каждом файле.
2. Найди противоречия и пробелы (например, разные цены на одно и то же).
3. Запомни в долговременной памяти: на вопросы клиентов отвечай только
   по файлам из knowledge/, если ответа нет — говори, что уточнишь.
```

**Ответ клиенту по базе**

```
Клиент написал: «[текст сообщения клиента]».
Подготовь ответ строго по файлам из knowledge/ в тоне из tone.md.
Правила: не придумывай цены, сроки и условия, которых нет в базе.
Если информации не хватает — напиши, что именно уточнить у меня.
В конце укажи, из каких файлов взят ответ. Клиенту пока не отправляй.
```

**Разбор входящих писем**

```
Посмотри новые письма в почте [адрес ящика] за [период].
Разложи их по группам: заявки, вопросы клиентов, счета и документы,
реклама и спам. Для каждой заявки и вопроса: от кого, суть в 1 строке,
срочность (высокая/средняя/низкая) и черновик ответа по базе knowledge/.
Ничего не отправляй и не удаляй — только сводка и черновики.
```

**Отчёт из таблицы**

```
Открой таблицу Google Sheets [название или ссылка], лист [название листа].
Сделай отчёт за [период]: итоги по [выручка/заявки/продажи], топ-5
[товаров/клиентов/менеджеров], сравнение с прошлым периодом, 3 вывода
и 2 рекомендации. Пришли отчёт файлом [PDF/DOCX] и коротко — текстом.
Таблицу не редактируй, только читай.
```

**Разбор PDF или таблицы из файла**

```
Я отправил файл [название]. Извлеки из него: [ключевые цифры / условия
договора / список позиций с ценами]. Оформи списком, отдельно отметь
спорные или непонятные места. Если в файле есть сроки и суммы —
вынеси их в начало.
```

**Генерация документа и отправка файлом**

```
Сделай коммерческое предложение для [имя клиента / компания] на услугу
[название услуги]. Цены и условия бери только из price.md и rules.md.
Структура: задача клиента, решение, этапы, сроки, стоимость, следующий шаг.
Сохрани в output_to_user/ в формате [DOCX/PDF] и пришли мне файлом.
```

**Вебхук от формы сайта**

```
Создай вебхук для формы заявок с сайта [адрес сайта].
Когда приходит заявка (поля: [имя, телефон, услуга, комментарий]):
1. Пришли мне сводку заявки в Telegram.
2. Подготовь черновик первого ответа клиенту по базе knowledge/.
3. Предложи добавить заявку в таблицу [название таблицы].
Ничего не отправляй клиенту без моего подтверждения.
Объясни простыми словами, что и куда вставить в настройках формы.
```

**Самопроверка агента**

```
Проверь свой последний ответ: «[текст ответа]».
1. Все ли факты (цены, сроки, условия) есть в knowledge/? Укажи источник.
2. Есть ли что-то придуманное или устаревшее?
3. Соответствует ли тон файлу tone.md?
4. Нет ли в ответе ключей, паролей и внутренних данных?
Выдай исправленную версию и список того, что поменял.
```

**Прогон тест-кейсов**

```
Вот тест-кейсы: [список вопросов клиентов, по одному в строке].
Ответь на каждый так, как ответил бы клиенту по базе knowledge/.
После каждого ответа поставь оценку: «есть в базе» / «частично» / «нет в базе».
В конце — список пробелов, которые мне нужно дописать в базу знаний.
```

## Частые ошибки

- Загрузить в базу всё подряд, включая старые прайсы → оставь только актуальные файлы, старые удали или пометь «архив».
- Вставить API-ключ или пароль прямо в чат → храни ключи в `.env` на сервере; если ключ попал в чат — сразу перевыпусти его.
- Подключить агента к основной почте или диску с полным доступом → заведи отдельный аккаунт и дай только нужные права (например, только чтение).
- Разрешить агенту отправлять письма и сообщения клиентам автоматически → сначала черновик тебе, отправка только после подтверждения.
- Проверить агента на двух лёгких вопросах и запустить → прогони 10+ тест-кейсов, включая вопросы, которых нет в базе.
- Исправлять ошибки агента в чате каждый раз заново → правь источник: файл базы знаний, инструкцию или долговременную память.
- Не обновлять базу после изменения цен или условий → поставь в файлах дату обновления и напоминание раз в месяц проверять актуальность.
